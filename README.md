# SSG Auto Tester

SmartApp (Blazor WebAssembly + DevExpress) тест орчныг **READ-ONLY** горимоор автоматаар smoke тест хийж,
SSG стандартын 2 тайланг гаргадаг локал вэб апп:

- `[Төсөл]-Test-Cases-v1.0.xlsx` — `07_Test-Cases-Загвар.xlsx` загвараар (томьёо, Data Validation, Dashboard хадгалагдана)
- `[Төсөл]-Test-Report-v1.0.docx` — `09_Test-Report-Загвар.docx` загвараар (9 бүлэг + Хавсралт А)

Хэрэглэгч URL оруулж, **тестийн урсгалаа** сонгоод эхлүүлнэ:

```
Нэвтрэх (гараар, заавал) → Smoke (сонголттой, READ-ONLY) → CRUD flow-ууд (сонголттой, 0..N)
```

Хөтөч харагдах горимд нээгдэж `/auth/login` руу очно — **хэрэглэгч өөрөө нэвтэрнэ** (нууц үг энэ системд
хэзээ ч орохгүй). Нэвтэрмэгц сонгосон алхмууд **нэг run, нэг browser session, нэг тайлан** дотор дараалан
ажиллаж, алдааг ангилж, GO/NO-GO шийдвэр гаргана.

---

## 1. Суулгах

### Локал (Python 3.11+)

```bash
cd ssg-smoke-tester
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
playwright install chromium          # Linux-д: playwright install --with-deps chromium
python scripts/make_report_template.py   # templates/report_tpl.docx-ийг (дахин) үүсгэнэ
```

Тайлангийн тоон утгыг LibreOffice-оор давхар тулгадаг тул **LibreOffice** (`soffice`) болон `pdftotext`
(poppler-utils) суулгахыг зөвлөж байна. Байхгүй бол тайлан үүснэ, гэхдээ тулгалт `skipped` гэж тэмдэглэгдэнэ.

### Docker

```bash
docker compose up --build
```

Үр дүн `./runs/`-д, сайтын тохиргоо `./config/`-д host машин дээр хадгалагдана. Порт зөвхөн `127.0.0.1`-д нээгдэнэ.

> ⚠ **Docker гар нэвтрэлтийг дэмжихгүй.** Контейнерт дэлгэц (display) байхгүй тул headed хөтөч нээгдэж
> хэрэглэгч нэвтрэх боломжгүй — run нэвтрэлтийн шатанд унана. Docker-ийг зөвхөн өмнөх run-уудын түүх,
> тайлан харахад ашиглана; тест ажиллуулахдаа **локал** (`python -m app`) горимыг хэрэглэнэ үү.

## 2. Ажиллуулах

```bash
python -m app                    # http://127.0.0.1:8000
python -m app --port 8080
```

Хөтчөөр `http://127.0.0.1:8000` нээнэ:

1. **Тест эхлүүлэх** — URL (жишээ `https://testaccounting.smartapp.mn/`), төслийн нэр (хоосон бол URL-аас:
   `testaccounting` → `Accounting`), QA Lead, **Тестийн урсгал** картууд:
   - 🔑 **Нэвтрэх (гараар)** — үргэлж асаалттай, унтраах боломжгүй.
   - 🔍 **Smoke (READ-ONLY)** — бүх модуль/цэсийг нээж хаана.
   - 🧾 **Форм шалгалт (READ-ONLY)** — smoke-ийн олсон Нэмэх/Засах товчтой цэс бүрийн Шинэ ба засварын формыг
     нээж, lookup бүрийг ачаалаад **хадгалалгүй** хаана (доор «Форм шалгалт»). Smoke шаардлагатай.
   - 🤖 **Автомат CRUD** — YAML бичихгүйгээр цэсний формыг илрүүлж бүртгэх → хайх → засах → устгах (доор
     «Цэсний үйлдлийн бүртгэл ба автомат CRUD»). Сонгосон үед «Өгөгдөл өөрчилнө — зөвхөн тест орчинд,
     run_tag-тай» анхааруулга гарна.
   - YAML-д тодорхойлсон (`config/sites/<host>.yaml → flows`) CRUD урсгалыг UI-аас сонгохгүй — зөвхөн
     CLI (`python -m app.flows --flow …`) болон API (`steps: [{"kind": "crud", "flow": …}]`)-аар ажиллана.

   «Нарийвчилсан тохиргоо» дотор: хүлээлт (ms), эрсдэлтэй цэсийг шалгах эсэх, давтан баталгаажуулалт,
   discovery-ийн дараа модуль сонгох. Товч: «Сонгосон N алхмыг эхлүүлэх».
2. **Явц** — эхлээд «🔑 Нээгдсэн хөтөч дээр нэвтэрнэ үү» мэдэгдэл ба үлдсэн хугацаа (`manual_login_timeout_ms`,
   анхдагч 5 мин). Алхам бүрийн төлөв (хүлээгдэж буй / ажиллаж байна / Pass / Fail / Blocked), CRUD flow-ын
   алхам бүрийн үр дүн, smoke-ийн progress bar, ETA, тоолуур, сүүлийн лог, «Зогсоох» (тэр хүртэлх үр дүнгээр
   тайлан гарна).
3. **Үр дүн** — GO/NO-GO баннер, KPI, bug-ийн хүснэгт (screenshot, stack trace, засах санал), шүүлттэй TC
   хүснэгт, xlsx/docx татах 2 том товч + screenshot zip, raw JSON, run.log.
4. **Түүх** — өмнөх run-ууд, хоёр run-ыг харьцуулах (шинэ / засагдсан / хэвээр байгаа bug).

Ижил төслийг дахин ажиллуулахад хувилбар автоматаар `v1.1`, `v1.2`… болно.

## 3. Юу шалгадаг вэ

| Илрэл | Хэрхэн | Эрэмбэ |
|---|---|---|
| .NET runtime уналт (`Unhandled Exception:`, `.NET runtime already exited` …) | console/pageerror + `window.__dead` | 🔴 Critical |
| Таб хаасны **дараах** хоцорсон уналт (ObjectDisposedException) | хаасны дараа 1.5 сек хүлээж шалгана | 🔴 Critical |
| Session тасрах (`/auth/login` руу шилжих) | URL; run түр зогсож гар дахин нэвтрэлт хүлээгээд цэсийг дахин шалгана | 🔴 Critical |
| UserRefreshToken / auth алдаа | console, модал | 🔴 Critical |
| SPA бүтэн reload (табууд алдагдах) | `performance.timeOrigin` өөрчлөгдөх | 🟡 Major |
| «Системийн алдаа» модал, SQL алдаа, алдааны toast | DOM | 🟡 Major |
| HTTP 5xx | response listener (503 + `msdeploy` → хүлээгээд дахин оролдоно) | 🟡 Major |
| «Loading…» 15 сек-ээс удаан / timeout | DOM, хугацаа | 🟡 Major (Blocked) |
| 403 / `_403` таб | DOM, HTTP | 🟢 Minor (≥5 цэсэд бол 🟡 Major) |
| Таб нээгдээгүй, табын нэр зөрсөн, console error, анхааруулгын toast | DOM | 🟢 Minor |

Recovery: runtime уналтын дараа reload (давтагдвал 2 дахь удаа), шаардлагатай бол гар дахин нэвтрэлт хүлээнэ; цэсийг
индексээр биш **href/нэрээр** дахин олно. Эрсдэлтэй цэсүүдийг (`risky_items`) хамгийн сүүлд шалгана.
Fail болсон цэс бүрийг төгсгөлд 1 удаа дахин шалгаж «Баталгаажсан (2/2)» / «1 удаа ажиглагдсан» гэж тэмдэглэнэ.
Ижил signature-тай илрэлүүд (GUID, тоог normalize хийсэн) **нэг bug** болж нэгтгэгдэнэ.

**GO/NO-GO:** Pass Rate ≥ 95%, Critical = 0, Major ≤ 2, Blocked = 0 — бүгд хангавал GO.

### READ-ONLY хамгаалалт

Апп зөвхөн цэс дарж, таб/цонхыг хаана. Цонх доторх товчноос зөвхөн `safe_dialog_buttons`
(OK, Хаах, Close, ×, Болих)-ыг дарна. `forbidden_button_words` (Хадгалах, Устгах, Батлах, Илгээх, Save, Delete …)
агуулсан товчийг хэзээ ч дарахгүй — логт «READ-ONLY: … татгалзав» гэж бичнэ. Энэ хамгаалалт зөвхөн smoke
алхмын үеэр үйлчилнэ (CRUD алхам зориуд өгөгдөл өөрчилнө).

### Нууцлал

Нэвтрэлт **зөвхөн гараар**: UI, API, config, env-д нэвтрэх нэр/нууц үгийн талбар байхгүй — хуучин клиент
`password` илгээвэл API үл тоомсорлоно. Системийн код нэвтрэх талбарыг хэзээ ч бөглөхгүй, зөвхөн
`selectors.app_ready` гарч ирэхийг хүлээнэ. Лог/тайлангаас JWT, `Bearer …`, `token=`/`password=` query
параметрийг шүүнэ. `auth.login new_context`-ын storage_state зөвхөн санах ойд байна.

## 3a. Тестийн урсгал (pipeline)

`app/pipeline/runner.py` → `PipelineRunner` нь browser, page, `Collector`, нэвтрэлт (`SessionGuard`) болон бүх
flow-ын хуваалцах нэг `FlowContext`-ийг (нэг `run_tag`) эзэмшинэ. Алхам бүрийг `app/pipeline/stages.py`-ын
registry-гээс (`STAGES`) дуудна — одоо `smoke`, `crud`; ирээдүйн `business`, `integration` төрлийг `Stage`-ээс
удамшуулж `@register`-ээр нэмнэ.

| Нөхцөл | Үр дүн |
|---|---|
| Smoke NO-GO | CRUD үргэлжилнэ (smoke нь crud-ийн нөхцөл биш) |
| Flow дотор алхам Fail | Дараагийн алхам Blocked; `always: true` (цэвэрлэх) алхам өгөгдөл нь байвал ажиллана |
| Нэг flow унасан | Дараагийн flow ажиллана |
| Session тасарсан (logout) | Run **түр зогсож** UI-д тод мэдэгдэл гарна; хэрэглэгч дахин нэвтэрмэгц тасарсан алхмаасаа үргэлжилнэ (CRUD алхмыг 1 удаа дахин ажиллуулна; `crud.create` бичлэг аль хэдийн үүссэн эсэхийг эхлээд хайж давхар үүсгэхгүй) |
| Дахин нэвтрэлтийн хугацаа хэтэрсэн | Үлдсэн бүх алхам Blocked |
| Эхний гар нэвтрэлт хугацаа хэтэрсэн | Бүх алхам Blocked (аппын bug үүсгэхгүй) |

**Аюулгүй байдал:** CRUD алхам зөвхөн `flow.allowed_hosts`-д таарах host дээр (анхдагч:
`test*.smartapp.mn`, `127.0.0.1`, `localhost`). Шалгалтыг **backend** хийнэ: `POST /api/runs` run эхлэхээс
өмнө 400 буцаана, `FlowEngine` мөн дахин шалгана. Бүртгэх/засах/устгах мөр заавал `run_tag` агуулна.

**API:**
- `GET /api/flows?url=…` → `[{name, code, steps, description, allowed, reason}]`
- `POST /api/runs` → `{"url": "...", "project": "...", "qa_lead": "...", "steps": [{"kind": "smoke", "modules": null},
  {"kind": "crud", "flow": "customer_group_crud"}]}`; `steps` байхгүй бол зөвхөн smoke.
- SSE: `stage` (`stage`: `auth` / `smoke` / `crud:<flow>`, `state`), `flow_step`, `waiting_login`
  (`reason`, `timeout_s`), `login_ok`, `session_lost`.
- `runs` хүснэгтэд `pipeline` (JSON) багана — хуучин `runs.db`-д эхлэхэд автоматаар нэмэгдэнэ.

**Тайлан:** нэг run → нэг xlsx + нэг docx. Flow-ын алхам бүр `TC-FLOW-<CODE>-<№>` TC (модуль «E2E»),
GO/NO-GO тооцоонд орно. `CODE` = flow-ын `code:` эсвэл нэрийн эхний үсгүүд (`customer_group_crud` → `CGC`).
Fail алхам → 🟡 Major bug (апп уналт / token алдаа илэрсэн бол 🔴 Critical), signature
`flow|<flow>|<алхам>|<мессеж, run_tag-гүй normalize>`. Docx-ийн «2.3. E2E урсгал»: flow бүрийн алхмууд,
`run_tag`, дамжсан өгөгдөл (үүсгэсэн бичлэгийн түлхүүр), цэвэрлэгээ амжилттай эсэх.

### Форм шалгалт (READ-ONLY, `formcheck` алхам)

Бодит SmartApp-д олдсон bug-уудын ихэнх (`Invalid column name 'ActiveStatus' / 'DistrictCode' / 'CostCenterId'`)
хадгалах биш **нээх** үед гардаг. Форм шалгалт өгөгдөл үүсгэлгүйгээр үүнийг бүх цэс дээр хурдан илрүүлнэ.
**Цэс сонголт.** Smoke дууссаны дараа Нэмэх/Засах товчтой цэсүүдийг модулиар бүлэглэн «🧾 Форм шалгалт хийх
цэсүүдийг сонгоно уу» картад санал болгоно (анхдагч: бүгд сонгогдсон). Сонголт ирэхгүй удвал (READ-ONLY тул)
бүх цэсийг шалгана; «Алгасах» → шалгахгүй. API: `POST /api/runs/{id}/form-select {"menus": [...]}`.

Цэс бүр = 1 урсгал (`TC-FORM-F01-…`, модуль нь цэсний модуль), хоёр бие даасан алхам. Засварын шалгалт
эхэнд — дөнгөж нээсэн, цэвэр жагсаалт дээр (Шинэ форм нээж хаасны дараа зарим жагсаалт хоосон харагддаг):

1. `form.check_edit` — жагсаалтын эхний мөрийг засварын горимд нээж (мөр дарах, эс бөгөөс «Засах»), ~1.5 сек
   хожуу гарах алдааг хүлээж шалгаад хадгалалгүй хаана. Жагсаалт хоосон бол: хайлтын текстийг цэвэрлэх →
   «Сэргээх» → «Шүүлтийн нөхцөл»-ийн эхлэх огноог 5 жил ухрааж «Шүүх». Тэгсэн ч хоосон бол Blocked
   («тест орчинд өгөгдөл байхгүй», bug биш).
2. `form.check_new` — «Нэмэх/Шинэ» → форм (цонх, шинэ таб; dropdown бол баримтын төрөл бүр, ≤5) нээгдэхэд
   системийн алдаа гарах эсэх → формын lookup ("...") бүрийг нээж мөр ачаалагдахыг хүлээнэ → ComboBox бүрийн
   жагсаалтыг нээж хаана → мөрийн grid байвал «+»-ээр мөр нэмж мөрийн lookup-уудыг (≤3) нээнэ. Бүгдийг
   **сонгохгүй**, формыг хадгалалгүй хаана. Алдааг бүгдийг цуглуулж (эхнийхээр зогсохгүй) Fail/bug болгоно.

**Session тасрах / үргэлжлүүлэх.** Run-ы дунд session тасарвал хөтөч урд гарч, UI-ийн таб анивчиж, дуу/мэдэгдэл
өгнө; дахин нэвтрэхийг `timing.relogin_timeout_ms` (анхдагч 30 мин) хүлээнэ. Хугацаа хэтэрсэн эсвэл зогсоосон
бол шалгагдаагүй цэсүүд Blocked биш **«ажиллаагүй»** болж `summary.resume`-д бүртгэгдэнэ; үр дүнгийн хэсгийн
«▶ Үлдсэн цэсүүдийг үргэлжлүүлэх» товч зөвхөн тэдгээрийг (smoke-гүй) шинэ run-аар шалгана.

**Хамрах хүрээ ба дүгнэлт:**
- **Дотоод табууд:** форм олон табтай бол (Анкет / Цалин …) таб бүрийг нээж lookup, ComboBox-ийг шалгана.
- **Засварын форм:** бичлэгийн өгөгдөл ачаалагдсан эсэх (бүх талбар хоосон → Fail), lookup/ComboBox/табууд —
  бодит бичлэг тул юу ч сонгохгүй, мөрийн grid-д мөр нэмэхгүй.
- **Шууд форм цэс** (цэс нь жагсаалт биш баримтын форм: Гүйлгээ, Нэхэмжлэх, Эхний үлдэгдэл …): формыг шууд шалгана;
  засварын шалгалт хамаарахгүй (`na`) — урьд нь «Шинэ дарахад форм нээгдсэнгүй» болж, формын огноог шүүлтүүр
  гэж өөрчилдөг байсан.
- **Blocked-ийн ангилал:** `nodata` (тест орчинд өгөгдөлгүй) ба `na` (хамаарахгүй) — TC болохгүй, GO/NO-GO-д
  тооцогдохгүй, «Тестлээгүй хэсгүүд»-д жагсаагдана; `tool` (хэрэгсэл UI-г таньсангүй) — Blocked хэвээр, тайланд тусад нь.
- **Анхааруулга (🟢 Minor, алхам Pass):** хоосон сонголтын жагсаалт (lookup/ComboBox/мөрийн lookup), удаан форм
  (`flow.slow_form_ms`, анхдагч 8 сек).
- **Үндсэн шалтгаанаар нэгтгэсэн bug:** ижил `Invalid column name 'X'` / `Invalid object name` / `DbSet` /
  Blazor уналт олон цэсэд гарвал НЭГ bug (хамаарах бүх цэс, TC).
- **Өмнөх хувилбартай харьцуулалт:** ижил систем дээрх өмнөх run-тай — шинээр эвдэрсэн / засагдсан / хэвээр
  эвдэрхий формууд (тайлангийн 2.3, `summary.form.compare`).

**Хурд.** SmartApp-д байнга нээлттэй (long-poll/polling) хүсэлт байдаг тул «сүлжээ тайван» болохыг хүлээх нь
алхам бүрт 10–30 сек хиймэл хүлээлт үүсгэдэг байсан. Одоо `timing.background_request_ms` (4 сек)-ээс удаан
нээлттэй хүсэлтийг арын холболт гэж үзэж ачаалалд тооцохгүй, тайвшрах хүлээлт `flow.settle_cap_ms` (1.5 сек)-ээр
хязгаарлагдана. Цэс бүрийн табыг шалгалтын дараа хаана (хуримтлагдвал апп удааширдаг); засварын форм «мөр
дарах» эсвэл «Засах»-аар нээгддэгийг эхний цэсээс суралцана. Алхам бүрийн тэмдэглэлд үе шатын хугацаа
(«⏱ цэс 0.4с · форм нээх 0.6с · lookup×3 2.1с · хаах 0.2с»), run.log-д цэс бүрийн хугацаа ба хамгийн удаан 3 цэс,
UI-ийн явцын мөрөнд ETA харагдана.

**Тусдаа тайлан.** Үндсэн тайлангаас гадна зөвхөн форм шалгалтын TC/bug-тай 2 файл үүснэ (UI: «🧾 Форм шалгалт —
Test Cases / Test Report» товч, татах: `/runs/{id}/download/form_xlsx`, `form_docx`):
`<Төсөл>-Form-Check-Test-Cases-<хувилбар>.xlsx`, `<Төсөл>-Form-Check-Report-<хувилбар>.docx`.

Өгөгдөл өөрчлөхгүй ч зарим систем «Шинэ» дарахад баримтын дугаар нөөцөлдөг тул зөвхөн `flow.allowed_hosts`
(тест орчин) дээр ажиллана. CLI: `python -m app.flows --url … --smoke --forms` (smoke-ийн бүх цэс, сонголтгүй) эсвэл
`--form "<module>|<folder>|<name>|<href>"`.

### Cloudflare / captcha-тай сайт — өөрийн Chrome-оор

Cloudflare Turnstile мэт captcha нь автоматжуулалтын хэрэгслээр нээсэн хөтчийг таньж нэвтрэлтийг хориглодог
(«Verification failed»). Хэрэгсэл captcha-г тойрч/хуурахгүй — оронд нь:

1. UI «🌐 Өөрийн Chrome-оор нэвтрэх» → «🌐 Chrome нээх»: тусдаа профайлтай (`%LOCALAPPDATA%\SSGAutoTester\chrome-profile`,
   таны хувийн профайлд хүрэхгүй) жинхэнэ Google Chrome remote debugging-тэй (зөвхөн 127.0.0.1:9222) нээгдэнэ.
2. Тэр Chrome дээр captcha-г давж **өөрөө нэвтэрнэ** (профайл хадгалагдах тул дараа нь дахин нэвтрэх шаардлага бага).
3. Тестээ эхлүүлнэ — хэрэгсэл тэр Chrome-д холбогдож шинэ таб дээр ажиллана; дуусахад зөвхөн өөрийн табаа хаана.

CLI: `python -m app.flows --url … --cdp [http://127.0.0.1:9222] …`. Урт хугацаандаа тест орчинд Turnstile-ийн
[тестийн sitekey](https://developers.cloudflare.com/turnstile/troubleshooting/testing/) тохируулах эсвэл
captcha-г унтраахыг хөгжүүлэгчдэд санал болгоно.

### Урсгал бичих (record → replay)

Нарийн бизнес урсгалыг (баримт бүртгэх → батлах, цалин бодох …) автоматаар таах боломжгүй тул хүн **нэг удаа
гараар** хийж, хэрэгсэл бичиж авна. Дараа нь тэр урсгалыг хүссэн үедээ дахин тоглуулна.

1. **Бичих.** UI «🎥 Урсгал бичих» → нэр өгөөд «● Бичиж эхлэх». Хөтөч нээгдэж та нэвтэрнэ, дараа нь урсгалаа
   гараар хийнэ. Бүртгэгдэж буй үйлдэл UI-д шууд харагдана. Дуусмагц «⏹ Дуусгах».
   Бичигч (app/flows/recorder.py) зөвхөн **ажиглана** (юу ч дарахгүй): цэс, товч (dropdown-ы төрөл орно),
   талбарын бөглөлт (шошгоор нь), checkbox, select/ComboBox сонголт, lookup ("...")-оос сонгосон мөр, жагсаалтын
   хайлт ба мөр сонголт, формын таб, мөрийн grid («+», нүд, нүдний lookup). Нууц үгийн талбар хэзээ ч бүртгэгдэхгүй.
   Мөн: текстгүй (icon) товч — icon классаар, товч биш дарагддаг холбоос/toolbar item, цонх доторх жагсаалтын мөр
   ба хайлт, мөрийн checkbox, бичлэг нээх «→» сум, талбарт Enter (Enter-ээр хадгалдаг форм; blur хийгээгүй утгыг
   алдахгүй). Календарь/dropdown доторх дарах үйлдэл мөр сонголт гэж бүртгэгдэхгүй (огноо нь талбарын утгаар).
   Засах/Устгах дарах үед мөр дараагүй бол тэр үеийн **фокуслагдсан мөрийг** тэмдэглэж, тоглуулахад яг тэр мөрийг
   сонгох алхам нэмнэ.
2. **YAML.** Үйлдлүүд ерөнхий `ui.*` алхам болно (`ui.menu`, `ui.click`, `ui.fill`, `ui.pick`, `ui.row`, …).
   Таны бичсэн текст утга `{run_tag} <утга>` болно (тоо хэвээр, өнөөдрийн огноо `{today}`) — тоглуулах бүрт
   давтагдашгүй тестийн өгөгдөл. Жагсаалтын мөр сонголт тэр утгаар хайгдана. Анхааруулга: устгах алхамгүй (өгөгдөл
   үлдэнэ), бодит бичлэг сонгосон, цэс нээх алхамгүй г.м. YAML-ыг UI-д засаад «💾 Хадгалах» →
   `config/recorded/<host>.yaml` (`flows: {"rec: <нэр>": …}`, код `R01…`, TC `TC-FLOW-R01-…`).
3. **Тоглуулах.** «Тестийн урсгал»-ын «🎥 Бичсэн урсгалууд»-аас сонгоно (smoke/форм шалгалттай хамт ч болно).
   Товч бүрийн дараа системийн алдааг, хадгалах/устгах төрлийн товчны дараа validation анхааруулгыг ч Fail гэж үзнэ.

**Аюулгүй байдал.** Зөвхөн `flow.allowed_hosts` дээр бичиж, тоглуулна. Тоглуулахад Хадгалах/Устгах/Тийм мэт
өгөгдөл өөрчлөх товчийг зөвхөн шинэ бичлэг (Нэмэх/Шинэ-ийн дараа) эсвэл `{run_tag}` агуулсан мөр сонгосны дараа
дарна; run_tag-гүй (бодит) мөр сонгосон бол **Blocked** — бодит өгөгдөлд хүрэхгүй.

### Цэсний үйлдлийн бүртгэл ба автомат CRUD

1. **Бүртгэл (READ-ONLY).** Smoke цэс бүрийн табыг нээсний дараа тухайн табын товч (идэвхгүй эсэхтэй нь),
   grid-ийн баганууд, хайлтын талбарыг **зөвхөн уншиж** бүртгэнэ (`crud_scan`, юу ч дарахгүй). Цэс ангилагдана:
   `full` (Нэмэх + Устгах) / `partial` / `none`; Батлах, Илгээх мэт процессын товч тусад нь тэмдэглэгдэнэ.
   Үр дүн `raw.json`-ын `results[].caps`-д, мөн host бүрийн **каталог** (`runs.db` → `menu_caps`)-д хадгалагдана.
2. **Цэс сонгох.** «🤖 Автомат CRUD» картаар:
   - **Smoke-ийн дараа сонгох** — smoke дуусмагц модуль сонгодог шиг «CRUD боломжтой N цэс» жагсаалт гарна
     (анхдагчаар **юу ч сонгогдоогүй**; хугацаа хэтэрвэл эсвэл «Алгасах» → өгөгдөл өөрчлөхгүй).
   - **Өмнөх smoke-ийн бүртгэлээс** — `GET /api/menus?url=…` каталогоос run эхлэхээс өмнө сонгоно (smoke-гүй ч болно).
3. **Автомат CRUD** (`autocrud` алхам, цэс бүр = 1 урсгал, `TC-FLOW-A01-…`):
   `crud.auto_create` (форм илрүүлж бөглөх) → хайх → `crud.auto_update` (Засах товч байвал) → хайх → устгах →
   устгагдсаныг шалгах. Утгыг шошгоос таана (`flow.auto`): түлхүүр талбар (Нэр/Тайлбар…) = `"{run_tag} автомат тест"`,
   код = `run_tag`, заавал имэйл/утас/тоо талбарт тохирох утга; заавал биш талбарыг хөндөхгүй.
   - «Нэмэх/Шинэ» дарсны дараа: **цонх** (popup форм) эсвэл **шинэ таб** (баримтын форм — хадгалсны дараа
     табыг хааж жагсаалт руу буцна) дээр ажиллана; **dropdown** (төрөл сонгох) гарвал сонголт хийхгүй алгасна.
     FormLayout caption-гүй формд шошгыг `aria-label`, `placeholder`, `label[for]` эсвэл input-ийн өмнөх текстээс таана.
   - Заавал **сонголтын** талбар (select, combobox, `...` товчтой lookup) — текст бичихгүй, эхний боломжит утгыг
     сонгоно (lookup: цонхны эхний мөрийг давхар дарна / «Сонгох»); формын дарааллаар (хамааралтай lookup).
     Lookup хоосон бол «шалгаж чадаагүй». Заавал огноо/checkbox талбар → «шалгаж чадаагүй».
   - Бүтэлгүйтвэл формыг хаахаас өмнө screenshot + оношлогоо (`meta.probe`: табууд, цонх, dropdown, input-уудын
     дээж ба шошгын таамаг) авч `run.log`, `raw.json`, YAML ноорогийн `diagnostics`-д хадгална.
   - Устгах товчгүй цэсэд **бичлэг үүсгэхгүй** (цэвэрлэх боломжгүй).
   - **Өөр бичлэгт хүрэхгүй хамгаалалт:** SmartApp-ын «Засах/Устгах» ФОКУСЛАГДСАН мөр дээр ажилладаг тул мөрийг
     (checkbox биш) текст нүдээр фокуслаж, фокуслагдсан мөр run_tag-тай эсэхийг шалгана; нээгдсэн засварын форм
     манай бичлэгийн утгыг агуулахгүй бол ХАДГАЛАХГҮЙ хаана. Форм ачаалагдах үед гарсан системийн алдаа
     (ж: `Invalid column name 'CostCenterId'`) → Fail (bug).
   - Баримтын мөр (inline grid): «+» → lookup-оос код → Tab-аар Дебет/Кредит (журнал: тэнцвэртэй 2 мөр);
     сүүлийн нүднээс Tab дарахгүй (SmartApp шинэ хоосон мөр үүсгэдэг).
   - Заавал сонголт/огноо талбар, эсвэл систем таасан утгыг хүлээж аваагүй (validation) бол
     «**автоматаар шалгаж чадаагүй**» — TC/bug үүсэхгүй (GO/NO-GO-д нөлөөлөхгүй), docx 2.2-т жагсаагдана.
   - Хадгалахад системийн алдаа / HTTP 5xx → жинхэнэ Fail → bug.
4. **YAML ноорог.** Автомат CRUD-ийн илрүүлсэн формоос `runs/<id>/flows-draft.yaml` үүснэ (UI: «flows YAML ноорог»).
   Бөглөж чадаагүй талбар `TODO`; шалгаж засаад `config/sites/<host>.yaml`-ын `flows:`-д хуулбал давтагдах,
   баталгаатай CRUD flow болно.

API: `GET /api/menus?url=&crud=full`, `POST /api/runs/{id}/crud-select {"menus": [...]}`,
`steps` дотор `{"kind": "autocrud", "menus": null | ["<module|folder|name|href>", …]}`,
SSE `crud_candidates`, татах `/runs/{id}/download/draft`.

**CLI** (мөн гар нэвтрэлттэй, headed):

```bash

```

## 7. Таамаглал

1. **Эрэмбийн нэршил.** xlsx-д загварын Data Validation утга (`🔴 Critical / 🟡 Major / 🟢 Minor`), docx-д
   загварын нэр (`P1 Critical / P2 High / P3 Medium`) хэрэглэв; mapping нь `severity.py`-д нэг газар.
2. **Bug Tracker-ийн журмын тайлбар** (загварын 10–12-р мөр) bug-уудын доор зөөгдөнө — 13-р мөрөөс bug эхлүүлбэл
   хүснэгт тасарч `COUNTA`-г буруутгадаг.
3. **TC-LOGIN-002 (Session ≥ 20 мин).** Run 20 минутаас богино бөгөөд logout ажиглагдаагүй бол `Pending`
   (бүрэн баталгаажаагүй) гэж үлдээнэ; logout ажиглагдвал `Fail` + 🔴 Critical bug.
4. **Bug статус** шинэ run-д үргэлж `Open`; docx-ийн «Fixed/Closed» хэсэг 0 гэж бичигдэнэ. Засагдсан эсэхийг
   «Түүх → харьцуулах»-аар хардаг.
5. **Test Report батлагдсан, Regression тест** нөхцөл автоматаар хангагдах боломжгүй тул «Хүлээгдэж байна» гэж
   бичигдэнэ; GO/NO-GO тооцоонд SSG-ийн 4 тоон нөхцөл (Pass Rate, Critical, Major, Blocked) ашиглагдана.
6. **Хоосон Fail-ийн давтан шалгалт** — анхны үр дүн (Fail) хадгалагдаж, зөвхөн баталгаажуулалтын тэмдэглэл нэмнэ.
7. **Токен сунгалт** тасарвал run түр зогсож, хэрэглэгч дахин гараар нэвтэрсний дараа тухайн цэсийг 1 удаа
   дахин шалгана; хоёр дахь удаа logout болбол `Blocked`.
10. **Олон role** дэмжихгүй: flow YAML-ын `role` нь зөвхөн мэдээллийн чанартай — өөр бол анхааруулга логлоод
    идэвхтэй (гараар нэвтэрсэн) session-ээр үргэлжилнэ. `auth.login fresh` дэмжигдэхгүй (тэмдэглэл үлдээнэ).
8. **Модулийн товчлол** YAML-д байхгүй бол нэрийг латинаар транслитерац хийж эхний үсгүүдээс үүсгэнэ.
9. **Screenshot** зөвхөн илрэлтэй цэсэд авна (1000 цэс × screenshot нь хэт их зай эзэлнэ).

## 8. Мэдэгдэж буй хязгаарлалт

- Бодит `*.smartapp.mn` орчин дээр туршаагүй (хөгжүүлэлтийн орчноос сүлжээгээр хандах боломжгүй байсан).
  DOM selector-ууд промптод өгөгдсөн бүтэц (`.modulenavbar`, `.mainnavbar`, `role=treeitem`, `dxbl-*`) болон mock
  сайт дээр баталгаажсан. **Эхлээд нэг модулиар** (`Нарийвчилсан тохиргоо → модуль сонгох`) туршиж, selector
  зөрвөл `config/sites/<host>.yaml`-д засна уу.
- Гүйцэтгэл: цэс бүрт ≈ 3 сек хүлээлт + 1.5 сек хаасны дараах шалгалт ≈ 5 сек → 1000 цэс ≈ 80–90 мин.
  Recovery (reload ~35MB WASM) олон гарвал хугацаа уртасна; `timing.wait_ms`-ыг сервертэй тааруулна.
- Нэг зэрэг нэг run ажиллуулахаар зохиосон (нэг хэрэглэгчийн локал хэрэгсэл).
- Гар нэвтрэлт шаардлагатай тул run бүр дэлгэцтэй (headed) машин дээр ажиллана — Docker/CI-д ажиллахгүй.
- `flow.selectors` / `flow.buttons` (форм, grid, Нэмэх/Хадгалах/Устгах товч) болон `customer_group_crud`-ын
  талбарын нэрс («Код», «Нэр») **зөвхөн mock сайт дээр** баталгаажсан.
- Автомат CRUD: `crud_scan.scope` (идэвхтэй табын агуулга), формын шошго/заавал тэмдэг (`*`, `required`)-ийг
  илрүүлэх нь бодит DevExpress DOM дээр баталгаажаагүй. Dropdown («…») доторх товч, мөр сонгосны дараа л гарч
  ирдэг товч бүртгэгдэхгүй. Мөртэй баримт, lookup/сонголтын заавал талбартай цэсүүд ихэвчлэн «автоматаар шалгаж
  чадаагүй» болно — тэдгээрт YAML ноорогоос flow бичнэ.
